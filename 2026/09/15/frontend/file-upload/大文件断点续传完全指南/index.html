前端大文件断点续传完全指南：Vue + Express/NestJS 实战
发表于 2026-09-15| 更新于 2026-09-18|前端
字数总计: 5.4k|阅读时长: 27 分钟

当你需要上传视频、压缩包等大文件时，网络中断就意味着从头再来？断点续传技术让你从上次中断的地方继续上传。本文将从前端视角出发，用 Vue 3 实现一个支持分片上传、断点续传、进度显示的完整方案，并提供 Express 和 NestJS 两种后端实现。

我们会实现一个能够自动分片、记录进度、失败重试、秒传检测的生产级文件上传组件。

一、核心原理与架构设计

什么是断点续传？

断点续传的本质是将大文件切成小块，分别上传，服务端再合并成完整文件。这样即使中途失败，也只需重传失败的分片。

graph LR
    A[大文件 100MB] --> B[切片 5MB × 20]
    B --> C[分片上传]
    C --> D{上传成功?}
    D -->|是| E[服务端合并]
    D -->|否| F[记录断点]
    F --> G[下次续传]
    E --> H[完整文件]

核心技术点对比

技术点 前端实现 后端实现 用途
文件切片 File.slice() - 将文件分成固定大小的块
文件哈希 spark-md5 crypto 生成文件唯一标识，用于秒传
进度追踪 XMLHttpRequest.upload.onprogress - 实时显示上传进度
并发控制 Promise.all() + 限流 - 控制同时上传的分片数
临时存储 localStorage fs.writeFile() 记录上传进度 / 存储分片
文件合并 - fs.createWriteStream() 将所有分片合并成完整文件

整体架构流程

sequenceDiagram
    participant U as 用户
    participant V as Vue前端
    participant E as Express/NestJS
    participant FS as 文件系统
    
    U->>V: 选择文件
    V->>V: 计算文件Hash (MD5)
    V->>E: 检查文件是否存在
    E->>FS: 查询上传记录
    alt 文件已存在
        E-->>V: 秒传成功
    else 文件不存在
        V->>V: 文件切片 (每片5MB)
        E-->>V: 返回已上传分片列表
        
        loop 上传每个分片
            V->>E: 上传分片 (带hash+index)
            E->>FS: 保存分片到临时目录
            E-->>V: 返回上传结果
            V->>V: 更新进度 (已传/总数)
        end
        
        V->>E: 请求合并分片
        E->>FS: 读取所有分片并合并
        E->>FS: 删除临时分片
        E-->>V: 返回文件URL
        V->>U: 显示上传完成
    end

四、核心优化点

1. 秒传检测流程

graph TD
    A[用户选择文件] --> B[计算文件Hash]
    B --> C{服务端检查Hash}
    C -->|文件已存在| D[秒传成功]
    C -->|文件不存在| E[开始分片上传]
    D --> F[直接返回文件URL]
    E --> G[正常上传流程]

通过文件 Hash 判断，相同文件只需上传一次，大幅提升重复文件的上传速度。

六、性能对比与优化建议

不同分片大小的性能对比

分片大小 网络请求数 (100MB) 合并耗时 断点续传粒度 推荐场景
1MB 100 快 精细 弱网环境、小文件
5MB 20 中等 平衡 通用场景（推荐）
10MB 10 慢 粗糙 强网环境、大文件

关键优化点

  1. 前端优化

    • 使用 Web Worker 计算文件 Hash，避免阻塞主线程
    • 分片大小根据网络状况动态调整
    • 使用 IndexedDB 存储更大的断点信息

  2. 后端优化

    • 使用流式写入减少内存占用
    • 分片存储使用 Hash 分级目录，避免单目录文件过多
    • 定期清理过期的临时分片

  3. 网络优化

    • 使用 HTTP/2 多路复用提升并发效率
    • 对小分片启用 gzip 压缩
    • CDN 加速文件下载

八、总结

本文从前端开发者的角度，完整实现了一个生产级的大文件断点续传方案。核心要点：

  1. 分片上传: 将大文件切成小块，降低单次请求失败的影响
  2. 断点续传: 保存上传进度，网络中断后可从断点继续
  3. 秒传检测: 通过文件 Hash 判断，相同文件直接返回
  4. 并发控制: 限制同时上传的分片数，提升稳定性
  5. 进度反馈: 实时显示上传进度，提升用户体验

技术栈总结

  • 前端: Vue 3 + TypeScript + spark-md5
  • 后端: Express / NestJS + multer + fs-extra
  • 核心 API: File.slice()、FileReader、FormData、XMLHttpRequest

下一步扩展

  1. 多线程上传: 使用 Web Worker 并行计算 Hash
  2. 云存储集成: 对接 OSS、S3 等云存储服务
  3. 视频切片: 支持 HLS/DASH 流式上传
  4. P2P 传输: WebRTC 实现点对点文件传输
